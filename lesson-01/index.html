1.1 数据生成

基于新生数据（DeepSeek 合成）讲解异步加载与字段映射
Explains asynchronous loading and field mapping using the new-student dataset (synthesized by DeepSeek)

你的原案例Your Original Case

本章采用中国石油大学（华东）2025 级新生数据，阐述数据的特性。为了防止数据隐私泄露，数据采用 DeepSeek 大模型生成。数据文件 data/students_synthetic.csv，含 50 条记录。

This chapter uses the 2025 new-student data from China University of Petroleum (East China) to illustrate the characteristics of data. To prevent data privacy leaks, the data was generated by the DeepSeek large language model. The data file contains 50 records.

嵌入理论：AI 合成数据的可信度边界Embedded Theory: The Trustworthiness Boundary of AI-Synthesized Data

数据质量四维度（Wang & Strong 1996）：准确性 / 完整性 / 一致性 / 时效性。

Four Dimensions of Data Quality (Wang & Strong 1996): Accuracy / Completeness / Consistency / Timeliness.

  • 完整性：字段齐全Completeness: all fields present
  • 准确性：姓名/籍贯是虚构的，不能用作真实人口分析Accuracy: names/hometowns are fictional, cannot be used for real demographic analysis
  • 采样偏差：模型倾向"看起来合理"的分布Sampling bias: the model favors "plausible-looking" distributions
课堂要点：Key Point: 教学场景使用合成数据没问题，但必须标注"合成数据"，避免学生误以为真实分布。 Using synthetic data in teaching is fine, but it must be labeled as "synthetic" to avoid students mistaking it for real distributions.

中文列名映射成英文变量名 —— 避免 JS 中带中文 key 引发语法/编码隐患。Map Chinese column names to English variable names — avoid syntax/encoding issues with Chinese keys in JS.

⭐ // 关键点 ①：字段映射 —— 中文 → 英文
const COLUMN_MAP = {
  "序号": "id",
  "姓名": "name",
  "性别": "gender",
  "生日": "birthday",

关键点解释：Key Point: 为什么不用中文 key？(1) JS 引擎对中文标识符的容错性差；(2) 后端、JSON、URL 编码都可能引入乱码；(3) IDE 自动补全、搜索、重构工具对中文支持不一致。最佳实践：CSV 用人可读的中文名，JS 内部统一英文变量。 Why not use Chinese keys? (1) JS engines have poor tolerance for Chinese identifiers; (2) Backend, JSON, URL encoding may introduce garbled text; (3) IDE autocomplete, search, and refactoring tools have inconsistent Chinese support. Best practice: Use human-readable Chinese names in CSV, unified English variables inside JS.

1.2 数据定义

DIKW 金字塔 —— 数据 → 信息 → 知识 → 智慧
DIKW Pyramid — Data → Information → Knowledge → Wisdom

你的原案例Your Original Case

DIKW 金字塔：数据是"原始数据"，信息是"组织好的数据"，知识是"模式/规律"，智慧是"判断/战略"。DIKW Pyramid: Data is "raw data", Information is "organized data", Knowledge is "patterns/rules", Wisdom is "judgment/strategy".

层Layer定义Definition回答的问题Answers
Data原始、离散的观察结果Raw, discrete observations—
Information经过处理、组织、赋予上下文的数据Processed, organized data with context谁 / 什么 / 何时 / 何地Who / What / When / Where
Knowledge对信息的进一步提炼和理解Further refinement and understanding of information如何How
Wisdom运用知识做出明智判断和战略决策Applying knowledge to make sound judgments and strategic decisions为什么 / 应该怎么做Why / What should be done

嵌入理论：可视化在 DIKW 中的位置Embedded Theory: Position of Visualization in DIKW

关键洞见：可视化主要把 Data 升到 Information，少数场景能升到 Knowledge，但难以跨越到 Wisdom。Key Insight: Visualization mainly elevates Data to Information, and in rare cases to Knowledge, but rarely crosses into Wisdom.

  • Data → Information：把表格"翻译"成可读图形（折线图、柱状图、热图）Data → Information: "translate" tables into readable graphics (line, bar, heat maps)
  • Information → Knowledge：模式发现需要统计模型辅助（机器学习）Information → Knowledge: pattern discovery needs statistical model assistance (machine learning)
  • Knowledge → Wisdom：决策与战略超出可视化能力Knowledge → Wisdom: decision-making and strategy exceed visualization capabilities

关键代码 ① DIKW 数据模型Key Code ① DIKW Data Model

⭐ // Data —— 原始离散值
const data = [632, 588, 701, 495, 677];

// Information —— 带标签的数据
const info = [
  { score: 632, name: '张伟', major: 'CS' },
  { score: 588, name: '李娜', major: 'EE' },
  { score: 701, name: '王磊', major: 'CS' }
];

// Knowledge —— 聚合后的模式
const knowledge = d3.rollup(info,
  v => ({ count: v.length, avg: d3.mean(v, d => d.score) }),
  d => d.major
);

// Wisdom —— 基于模式的决策
// → "CS 专业平均分最高，建议增加招生名额"
关键点解释：Key Point: 从 Data 到 Wisdom 是不断抽象的过程。可视化在 Data→Information 阶段最有效，能直接把数字变成人眼可感知的图形。 From Data to Wisdom is a process of increasing abstraction. Visualization is most effective at the Data→Information stage, directly turning numbers into visually perceivable graphics.

1.3 数据属性

Stevens 测量尺度 × Mackinlay 视觉通道排序
Stevens Measurement Scales × Mackinlay Visual Channel Ranking

你的原案例（3 大类）Your Original Case (3 Categories)

  • 类别型属性：符号或名称，无顺序关系（性别、姓名）Categorical attribute: symbols or names with no ordering (gender, name)
  • 序数型属性：属性值有顺序（学位：本科/硕士/博士）Ordinal attribute: values have an order (degree: bachelor/master/PhD)
  • 数值型属性：定量方法（年龄、价格）Numerical attribute: quantitative measures (age, price)

嵌入理论：Stevens 测量尺度（1946）Stevens Measurement Scales (1946)

类别Category允许的运算Allowed Operations典型示例Examples
名义 Nominal等价 / 不等价equality / inequality姓名、性别name, gender
序数 Ordinal+ > <等级、班级序号rank, class number
区间 Interval加减+/−温度（°C）temperature (°C)

嵌入理论：Mackinlay 视觉通道排序（1986）Mackinlay Visual Channel Ranking (1986)

  • 定量型：位置、长度、角度 → 适合比率 / 区间Quantitative: position, length, angle → suitable for ratio / interval
  • 顺序型：亮度、密度、饱和度 → 适合序数Ordinal: lightness, density, saturation → suitable for ordinal
  • 定性型：色相、形状 → 适合名义Categorical: hue, shape → suitable for nominal
核心发现：Key Finding: 位置是最强的定量通道；色相是最强的定性通道。错配 → 信息丢失。 Position is the strongest quantitative channel; hue is the strongest categorical channel. Mismatch → information loss.

关键代码 ① 比例尺选型Key Code ① Scale Selection

⭐ // 比率型数据 → scaleLinear（连续定量）
const x = d3.scaleLinear().domain([0, 100]).range([0, 800]);

// 名义/序数型数据 → scaleBand（离散分类）
const x = d3.scaleBand()
  .domain(["软件1班", "软件2班"])
  .range([0, 800]);
关键点解释：Key Point: D3 比例尺的 domain() 是数据域（输入），range() 是值域（输出像素）。选错比例尺是初学者最常犯的错：类别数据用 scaleLinear 会算出没有意义的中间值（如 0.5 班）。 In D3 scales, domain() is the data domain (input), range() is the pixel range (output). Choosing the wrong scale is the most common beginner mistake: using scaleLinear on categorical data produces meaningless intermediate values (e.g., "0.5 class").

D3 把 JavaScript 原生数组与函数式编程结合，提供一组高阶变换函数。本章重点掌握 8 个：D3 combines native JavaScript arrays with functional programming, providing a set of higher-order transform functions. This chapter focuses on 8 key functions:

关键代码 ① 8 种变换函数Key Code ① 8 Transform Functions

const data = [
  { name: 'Alice', major: 'CS',   score: 88 },
  { name: 'Bob',   major: 'CS',   score: 72 },
  { name: 'Cara',  major: 'Art',  score: 95 },
  { name: 'Dan',   major: 'Art',  score: 60 },
  { name: 'Eve',   major: 'CS',   score: 81 },
  { name: 'Frank', major: 'Math', score: 90 }
];

// 1. filter —— 过滤
const passed = data.filter(d => d.score >= 60);

// 2. map —— 映射
const names = data.map(d => d.name);

// 3. group —— 按键分组，返回 Map
const byMajor = d3.group(data, d => d.major);

// 4. rollup —— 分组 + 聚合
const avgByMajor = d3.rollup(data,
  v => d3.mean(v, d => d.score),
  d => d.major);

// 5. bin —— 分箱（直方图）
const bins = d3.bin().value(d => d.score)(data);

// 6. extent —— 求极值
const [lo, hi] = d3.extent(data, d => d.score);
关键点解释：Key Point: d3.group 返回嵌套 Map，d3.rollup 在分组后直接聚合。d3.bin 用于直方图自动分箱。 d3.group returns a nested Map; d3.rollup aggregates directly after grouping. d3.bin is for automatic histogram binning.

1.5 D3 数据选择器

Data-Join 三态：enter / update / exit
Data-Join: enter / update / exit — the soul of D3

你的原案例Your Original Case

D3 的核心思想是 Data-Join：把「数据数组」与「DOM 选集」按键（key）对齐，得到 enter / update / exit 三态。The core idea of D3 is Data-Join: align the "data array" with the "DOM selection" by key, yielding three states: enter / update / exit.

  • enter：数据有、DOM 无 → 新建元素enter: data exists, DOM doesn't → create new elements
  • update：数据有、DOM 有 → 更新属性update: both data and DOM exist → update attributes
  • exit：数据无、DOM 有 → 移除元素exit: data gone, DOM exists → remove elements
关键：Key: 切换到【▶️ 演示】Tab，点「刷新数据」按钮，可直观看到 enter/update/exit 的三种过渡动画。 Switch to the [▶️ Demo] tab and click the "Refresh Data" button to visually see the three transition animations of enter/update/exit.

关键代码 ① 标准 Data-Join 模板Key Code ① Standard Data-Join Template

⭐ function render(data) {
  const sel = d3.select('svg')
    .selectAll('rect.bar')
    .data(data, d => d.id);           // 关键：传 key 函数

  // enter —— 数据有、DOM 无
  sel.enter().append('rect').attr('class', 'bar')
    .attr('y', h).attr('height', 0)    // 从 0 长出来
    .attr('fill', '#34d399')           // 绿色 = 新增
    .merge(sel)                         // 与 update 合并
    .transition().duration(600)
    .attr('y', d => h - d.value * 4)
    .attr('height', d => d.value * 4)
    .attr('fill', '#60a5fa');           // 蓝色 = 更新

  // exit —— 数据无、DOM 有
  sel.exit().transition().duration(400)
    .attr('fill', '#f87171')            // 红色 = 退出
    .attr('y', h).attr('height', 0)
    .remove();
}
关键点解释：Key Point: 如果不传 key 函数 d => d.id，D3 默认按下标匹配，会导致 enter/update/exit 的行为不可预期。必须用 function() 而非箭头函数，因为 D3 回调里要用 this 访问当前元素。 If no key function d => d.id is provided, D3 matches by index by default, leading to unpredictable enter/update/exit behavior. You must use function() instead of arrow functions, because D3 callbacks need this to access the current element.
