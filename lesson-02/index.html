2.1 Card 数据流模型

把可视化流程抽象为一串可组合的 Card，每张 Card 接收上一张的输出、产出给下一张
Abstract the visualization pipeline into a chain of composable Cards; each Card takes the previous Card's output and produces output for the next.

第2章我们引入一个统一的思维模型：把数据可视化的整个过程抽象为一组「Card」。每张 Card 接收上一张的输出，产出给下一张。In Chapter 2 we introduce a unified mental model: abstract the entire data visualization process into a set of "Cards". Each Card takes the previous Card's output and produces output for the next.

Card 模型链路：Card Model Pipeline: 原始数据 → 清洗 Card → 变换 Card → 布局 Card → 渲染 Card → 交互 Card。每张 Card 都可被替换、组合、复用。 Raw Data → Clean Card → Transform Card → Layout Card → Render Card → Interact Card. Each Card can be replaced, combined, and reused.
  • Card 之间通过明确的数据契约传递（输入/输出类型一致即可插拔）Cards communicate through explicit data contracts (plug-and-play as long as input/output types match)
  • 布局 Card 把数据结构转换为带坐标的几何描述The Layout Card converts data structures into coordinate-bearing geometric descriptions
  • 渲染 Card 把几何描述转换为 SVG/Canvas 元素The Render Card converts geometric descriptions into SVG/Canvas elements
  • D3 的 Selection 就是渲染 Card，d3.tree / d3.pack 就是布局 CardD3's Selection is the Render Card; d3.tree / d3.pack are Layout Cards

Card 模型伪代码Card Model Pseudocode

// 数据可视化 = 一串 Card 的流水线
const pipeline = [
  loadCard,     // 原始 CSV → 数组
  cleanCard,    // 数组 → 清洗后数组
  transformCard,// 数组 → 树/Map/...
  layoutCard,   // 树 → 带 {x, y} 的节点
  renderCard,   // 节点 → SVG/DOM
  interactCard  // DOM → 事件监听
];
// D3 里的对应关系：
// d3.csv       → loadCard
// d3.filter    → cleanCard
// d3.rollup    → transformCard
// d3.tree      → layoutCard
// d3.select().enter → renderCard
// .on('click') → interactCard

2.2 新生数据 → 分类树

用 d3.rollup 把扁平的新生记录按专业 → 性别 → 学位递归分组
Use d3.rollup to recursively group flat student records by major → gender → degree

我们把第1章合成的「新生数据」按字段递归分组：专业 → 性别 → 学位等级，得到一棵分类树。这正是 d3.rollup 的典型用法。We recursively group the "new-student data" synthesized in Chapter 1 by fields: major → gender → degree level, yielding a classification tree. This is the canonical use case for d3.rollup.

这棵分类树的叶子节点是学生本人，内部节点是分类键。它是后续树形布局（2.3 / 2.4）的输入。The leaf nodes of this classification tree are the students themselves; the internal nodes are the classification keys. It serves as input for the subsequent tree layouts (2.3 / 2.4).

Map → hierarchy：Map → hierarchy: d3.rollup 返回的是嵌套 Map，需要配合 d3.hierarchy(root, children) 把它转换成 D3 能处理的树结构。 d3.rollup returns a nested Map, which must be paired with d3.hierarchy(root, children) to convert it into a tree structure that D3 can process.
  • d3.group 只分组不聚合，d3.rollup 分组 + 聚合函数d3.group only groups without aggregation; d3.rollup groups + applies an aggregation function
  • 多层分组传多个 key 函数：d.rollup(data, fn, k1, k2, k3)Pass multiple key functions for multi-level grouping: d.rollup(data, fn, k1, k2, k3)
  • 输出 Map 的层级数 = key 函数数量The number of Map levels in the output equals the number of key functions

d3.rollup 两层分组 + hierarchyd3.rollup Two-Level Grouping + hierarchy

const students = [
  { major: 'CS',  gender: 'M', name: 'Alice',  grade: 'A' },
  { major: 'CS',  gender: 'F', name: 'Bob',    grade: 'B' },
  { major: 'Art', gender: 'F', name: 'Cara',   grade: 'A' },
  { major: 'Art', gender: 'M', name: 'Dan',    grade: 'C' },
  { major: 'Phy', gender: 'F', name: 'Eve',    grade: 'A' }
];

// 按 [major, gender] 两层 rollup，叶子是学生数组
const rolled = d3.rollup(
  students,
  v => v,                       // 聚合函数：保留整组
  d => d.major,                 // 第1层 key
  d => d.gender                 // 第2层 key
);
// Map { 'CS' → Map { 'M' → [Alice], 'F' → [Bob] }, ... }

// 用 d3.hierarchy 把嵌套 Map 转成标准树
const root = d3.hierarchy(
  { name: '全部', children: rolled },
  node => node.children instanceof Map
    ? [...node.children].map(([k, v]) => ({ name: k, children: v }))
    : []
);
root.descendants().forEach(d => console.log(d.data.name, d.depth, d.parent));

2.3 树形列表

分类树既可以渲染成嵌套 ul，也可以喂给 d3.hierarchy 转成布局输入
Classification trees can be rendered as nested ul or fed to d3.hierarchy for layout input

分类树既可以用嵌套 <ul> 渲染成「树形列表」HTML 结构，也可以用 D3 的 d3.hierarchy 转换为带深度、父指针的对象，再交给布局算法。A classification tree can be rendered as a "tree list" HTML structure using nested <ul>, or converted by D3's d3.hierarchy into objects with depth and parent pointers, then handed to layout algorithms.

  • HTML 树形列表：直接嵌套 ul/li，CSS 控缩进与连接线HTML tree list: directly nest ul/li, CSS controls indentation and connecting lines
  • D3 hierarchy：调用 d3.hierarchy(root, children)，自动算 depth、height、parentD3 hierarchy: call d3.hierarchy(root, children), automatically computes depth, height, parent
  • 可对 hierarchy 调 .sum()、.sort()、.count()Can call .sum(), .sort(), .count() on the hierarchy
实用工具：Useful Utilities: hierarchy.descendants() 返回所有节点数组，hierarchy.links() 返回所有父子连线数组 —— 这两个就是后面 Data-Join 的数据源。 hierarchy.descendants() returns an array of all nodes; hierarchy.links() returns an array of all parent-child links — these two are the data sources for the later Data-Join.

递归渲染树形 HTML 列表Recursively Render Tree HTML List

function renderTree(root, container) {
  const ul = d3.select(container).append('ul')
    .attr('class', 'tree-list').style('padding-left', '16px');
  const items = ul.selectAll('li').data(root.children);
  const enter = items.enter().append('li')
    .style('padding', '3px 0').style('cursor', 'pointer');
  enter.append('span').text(d => d.data.name)
    .on('click', function () {
      d3.select(this).style('color', '#ef4444');
    });
  // 递归处理子节点
  enter.each(function (d) {
    if (d.children) renderTree(d, this);
  });
}
renderTree(root, '#tree-root');

2.4 Reingold-Tilford 布局

D3 的 d3.tree() / d3.cluster() 实现，同层等距、子树不重叠、整体居中
Implemented by D3's d3.tree() / d3.cluster(): equal spacing at the same level, non-overlapping subtrees, centered overall

Reingold 与 Tilford 在 1981 年提出的层次树布局算法：让同层节点等距排列，子树之间不重叠，整体紧致居中。D3 的 d3.tree() 即为其实现。Reingold and Tilford proposed this hierarchical tree layout algorithm in 1981: nodes at the same level are evenly spaced, subtrees do not overlap, and the overall layout is compact and centered. D3's d3.tree() is its implementation.

d3.cluster() 是它的变种：所有叶子节点对齐到同一深度，适合展示聚类结果。d3.cluster() is a variant: all leaf nodes are aligned to the same depth, suitable for displaying clustering results.

关键参数二选一：Key Parameter (one of two): tree.size([w, h]) 控制输出空间（根在 0，叶子自动铺满 w）；tree.nodeSize([w, h]) 以节点尺寸为单位，根不一定在 (0,0)。 tree.size([w, h]) controls the output space (root at 0, leaves auto-fill w); tree.nodeSize([w, h]) uses node size as the unit, and the root is not necessarily at (0,0).
  • 先 treeLayout(root)，再读每个 node 的 .x / .yFirst call treeLayout(root), then read each node's .x / .y
  • 水平树用 d3.linkHorizontal()，垂直树用 d3.linkVertical()Use d3.linkHorizontal() for horizontal trees, d3.linkVertical() for vertical trees
  • node 坐标是数值，记得 translate(x, y) 应用Node coordinates are numeric; remember to apply translate(x, y)

完整 Reingold-Tilford 水平树模板Complete Reingold-Tilford Horizontal Tree Template

const W = 760, H = 360;
const svg = d3.select('#demo-2-4-svg').append('svg')
  .attr('viewBox', `0 0 ${W} ${H}`).attr('width', '100%');

// 1. 准备数据
const treeData = {
  name: '根',
  children: [
    { name: 'A', children: [ { name: 'A-1' }, { name: 'A-2' } ] },
    { name: 'B' },
    { name: 'C', children: [ { name: 'C-1' }, { name: 'C-2' }, { name: 'C-3' } ] }
  ]
};

// 2. 构建 hierarchy
const root = d3.hierarchy(treeData);

// 3. 跑布局（二选一：tree vs cluster）
const layout = d3.tree().size([H - 40, W - 140]);
layout(root);  // 节点被赋予 .x / .y

// 4. 画连线
const g = svg.append('g').attr('transform', 'translate(60,20)');
g.selectAll('path.link').data(root.links()).enter().append('path')
  .attr('class', 'link')
  .attr('d', d3.linkHorizontal().x(d => d.y).y(d => d.x))
  .attr('fill', 'none').attr('stroke', '#cbd5e1');

// 5. 画节点
const node = g.selectAll('g.node').data(root.descendants())
  .enter().append('g').attr('class', 'node')
  .attr('transform', d => `translate(${d.y},${d.x})`);
node.append('circle').attr('r', 5).attr('fill', '#2563eb');
node.append('text').attr('x', 10).attr('y', 4)
  .attr('font-size', 12).text(d => d.data.name);

2.5 DOM 事件机制与事件委托

冒泡 / 捕获 / 委托：父容器绑一个监听器管理所有子节点
Bubbling / Capturing / Delegation: one listener on the parent manages all children

当树形列表有成百上千节点时，给每个 li 都绑 onclick 会浪费内存。事件委托的思路是：把监听器绑在父容器上，靠 e.target 判断实际被点的是谁。When a tree list has hundreds or thousands of nodes, binding onclick to every li wastes memory. The idea of event delegation is: bind the listener to the parent container, and use e.target to determine who was actually clicked.

  • 事件冒泡：子 → 父 → 根（默认监听器捕获冒泡阶段）Event bubbling: child → parent → root (default listeners catch the bubbling phase)
  • 事件捕获：根 → 父 → 子（addEventListener(fn, true)）Event capturing: root → parent → child (addEventListener(fn, true))
  • 委托：监听父级，靠 e.target.closest('li') 找到目标节点Delegation: listen on the parent, use e.target.closest('li') to find the target node
提示：Tip: 切换到右侧【▶️ 演示】Tab，点击树节点或下方列表项，可观察事件委托的实际效果。 Switch to the [▶️ Demo] tab on the right, click tree nodes or list items below, and observe the actual effect of event delegation.

const ul = document.querySelector('#tree-list');
ul.addEventListener('click', function (e) {
  // 关键：从实际被点击的 e.target 向上找到符合条件的最近祖先
  const li = e.target.closest('li');
  if (!li) return;          // 点到了 ul 本身，不是 li
  console.log('clicked:', li.dataset.id);
  // 高亮
  ul.querySelectorAll('li').forEach(x => x.classList.remove('active'));
  li.classList.add('active');
});
