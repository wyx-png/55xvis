4.1 Crime 数据坐标变换

把美国各州犯罪率数据映射到二维屏幕坐标
Mapping US state crime rates to 2D screen coordinates

本章使用经典的 Crime 数据集（美国 21 个州的谋杀率、抢劫率、入室盗窃、人口等字段），任务是画出「各州谋杀率 vs 抢劫率」的散点图。This chapter uses the classic Crime dataset (murder rate, robbery rate, burglary, population, etc. for 21 US states). The task is to draw a scatter plot of "murder rate vs robbery rate" for each state.

散点图看似简单，但背后隐藏了可视化的核心问题 —— 坐标变换（Coordinate Transform）：数据空间 [0, 1000] 的数值范围如何翻译到屏幕上 [0, 760] 的像素范围？A scatter plot looks simple, but it hides the core problem of visualization — Coordinate Transform: how do we map the numerical range of data space [0, 1000] to the pixel range of screen space [0, 760]?

核心问题：数据范围 [0, 1000] 与屏幕范围 [0, 760] 不一致 —— 必须用 d3.scaleLinear() 把前者「挤压/拉伸」到后者。Core Problem: The data range [0, 1000] does not match the screen range [0, 760] — we must use d3.scaleLinear() to "squeeze/stretch" the former into the latter.
  • X 轴：murder 字段，范围约 [1, 10] → 横向 700pxX axis: murder field, range roughly [1, 10] → 700px wide
  • Y 轴：robbery 字段，范围约 [20, 180] → 纵向 240px（注意 Y 轴要翻转）Y axis: robbery field, range roughly [20, 180] → 240px tall (note: Y axis must be flipped)
  • 每个点的半径可以映射到 population（州人口），形成气泡图Each point's radius can be mapped to population (state population), forming a bubble chart

读取 Crime 数据 + 定义 scaleRead Crime Data + Define Scales

d3.csv('../data/crime.csv').then(function (rows) {
  // rows 是数组，每个元素是一个州的对象
  // { state: 'AL', murder: '8.6', robbery: '90',
  //   burglary: '700', theft: '2500', population: '4900' }

  var M = { l: 50, r: 20, t: 30, b: 50 };
  var W = 720, H = 280;

  // X 轴：murder 谋杀率 [1, 10]
  var sx = d3.scaleLinear()
    .domain([1, 10])
    .range([M.l, W - M.r]);

  // Y 轴：robbery 抢劫率 [20, 180]，注意翻转
  var sy = d3.scaleLinear()
    .domain([20, 180])
    .range([H - M.b, M.t]);

  // 画散点：sx(8.6) → 像素 x，sy(90) → 像素 y
  rows.forEach(function (d) {
    d3.select('svg').append('circle')
      .attr('cx', sx(+d.murder))
      .attr('cy', sy(+d.robbery))
      .attr('r', 6);
  });
});

Y 轴为什么要翻转？Why Flip the Y Axis?

// 数学坐标系：y 越大越往上
// 屏幕坐标系：y 越大越往下
// d3.scaleLinear().range([H - M.b, M.t]) 等价于把大值映射到小像素
// 这样 y=180 会出现在顶部（M.t），y=20 出现在底部（H-M.b）
// → 视觉上就和数学坐标系一致了

4.2 三层坐标变换

把变换拆成三层，层层可换、可调试
Split the transform into three swappable, debuggable layers

直接写一个 scale = d3.scaleLinear().domain(...).range(...) 虽然能跑，但后续改 margin、改坐标轴方向、加 zoom 时会牵一发动全身。Writing a single scale = d3.scaleLinear().domain(...).range(...) works, but later changes to margins, axis direction, or adding zoom will have cascading effects.

更好的做法是把坐标变换拆成 三层，每层只干一件事：A better approach is to split the coordinate transform into three layers, each doing one thing:

  • 数据层 Data-scale：原始数据 → 归一化 [0, 1]，只关心数据本身Data layer (Data-scale): raw data → normalized [0, 1], concerns only the data itself
  • 几何层 Geometry-scale：归一化值 → 屏幕像素，处理 margin、翻转 Y 轴Geometry layer (Geometry-scale): normalized values → screen pixels, handles margins and Y-axis flipping
  • 视图层 View-transform：SVG transform 属性，处理平移、旋转、缩放（zoom）View layer (View-transform): SVG transform attribute, handles translation, rotation, and zoom
好处：三层解耦后，改数据范围只碰数据层，改画布尺寸只碰几何层，加交互只碰视图层。调试时每层都可以单独画出来验证。Benefit: With three decoupled layers, changing the data range only touches the data layer, changing canvas size only touches the geometry layer, and adding interaction only touches the view layer. Each layer can be drawn and verified independently during debugging. 
// ===== 第一层：数据层 =====
// 只管数据本身，把原值归一化到 [0, 1]
var dataScaleX = d3.scaleLinear().domain([1, 10]).range([0, 1]);
var dataScaleY = d3.scaleLinear().domain([20, 180]).range([0, 1]);

// ===== 第二层：几何层 =====
// 归一化值 → 屏幕像素，处理 margin 和翻转
var geoScaleX = d3.scaleLinear().domain([0, 1]).range([M.l, W - M.r]);
var geoScaleY = d3.scaleLinear().domain([0, 1]).range([H - M.b, M.t]);

// 组合：值 → 像素
function x(v) { return geoScaleX(dataScaleX(v)); }
function y(v) { return geoScaleY(dataScaleY(v)); }

// ===== 第三层：视图层 =====
// SVG transform，处理整体平移、缩放、旋转
var viewGroup = svg.append('g').attr('class', 'view-layer')
  .attr('transform', 'translate(0,0)');

// 如果要加 zoom，只改视图层
svg.call(d3.zoom().on('zoom', function () {
  viewGroup.attr('transform', d3.event.transform);
}));

4.3 10 种曲线拟合

同一份散点，用 10 种 d3.curve* 去拟合，结果大相径庭
Fit the same scatter points with 10 d3.curve* generators — very different results

给定一组散点，我们可以用不同的曲线生成器（curve generator）连接它们。D3 内置了 10+ 种 d3.curve*，每种背后对应一种插值算法：Given a set of scatter points, we can connect them with different curve generators. D3 ships with 10+ d3.curve* generators, each backed by a different interpolation algorithm:

  • 线性 Linear：最朴素，两点之间直线Linear: the simplest, straight line between two points
  • Basis：B 样条，平滑但可能不经过原始点Basis: B-spline, smooth but may not pass through original points
  • BumpX / BumpY：光滑的凸起过渡，常用于 step 图BumpX / BumpY: smooth bump transitions, often used in step charts
  • Cardinal / CatmullRom：Cardinal 样条，保证经过所有控制点Cardinal / CatmullRom: Cardinal spline, guaranteed to pass through all control points
  • MonotoneX / MonotoneY：单调插值，不会产生不自然的震荡MonotoneX / MonotoneY: monotonic interpolation, no unnatural oscillation
  • Natural：自然三次样条，端点二阶导数为零Natural: natural cubic spline, second derivative is zero at endpoints
  • Step：阶梯函数，常量段连接Step: step function, connected by constant segments
实践建议：折线图首选 d3.curveMonotoneX（不会过冲）；需要强调「经过每个点」用 d3.curveCardinal；柱状图的连线用 d3.curveStep。Practical Advice: For line charts, prefer d3.curveMonotoneX (no overshoot); when emphasizing "passing through every point", use d3.curveCardinal; for bar chart connectors, use d3.curveStep. 
var points = [
  { x: 0, y: 5 }, { x: 1, y: 9 }, { x: 2, y: 13 },
  { x: 3, y: 14 }, { x: 4, y: 18 }, { x: 5, y: 21 },
  { x: 6, y: 19 }, { x: 7, y: 24 }, { x: 8, y: 26 }
];

var curves = [
  ['Linear',       d3.curveLinear],
  ['Basis',        d3.curveBasis],
  ['BumpX',        d3.curveBumpX],
  ['BumpY',        d3.curveBumpY],
  ['Cardinal',     d3.curveCardinal],
  ['CatmullRom',   d3.curveCatmullRom],
  ['MonotoneX',    d3.curveMonotoneX],
  ['MonotoneY',    d3.curveMonotoneY],
  ['Natural',      d3.curveNatural],
  ['Step',         d3.curveStep]
];

curves.forEach(function (c) {
  var name = c[0], curve = c[1];
  var lineGen = d3.line()
    .x(function (d) { return sx(d.x); })
    .y(function (d) { return sy(d.y); })
    .curve(curve);
  svg.append('path')
    .attr('d', lineGen(points))
    .attr('fill', 'none')
    .attr('stroke', '...')
    .attr('data-curve', name);
});
对比：Basis 曲线不经过原始数据点（只逼近），Cardinal 和 MonotoneX 必须经过每个点。拟合实验时注意这个区别。Comparison: The Basis curve does not pass through the original data points (it only approximates); Cardinal and MonotoneX must pass through every point. Keep this distinction in mind during fitting experiments.

4.4 Cleveland 45° 倾角

人眼对折线图斜率最敏感的角度约在 45°
The human eye is most sensitive to line-chart slopes near 45°

统计学家 William Cleveland 在 1984 年通过用户实验发现：人眼判断两条折线之间的角度差异时，当角度接近 45° 时判别力最强，过陡（>70°）或过平（<20°）都会让趋势判断失真。Statistician William Cleveland found in a 1984 user study that when judging the angular difference between two line charts, discrimination is strongest when the angle is near 45°. Too steep (>70°) or too flat (<20°) both distort trend perception.

  • 过陡：趋势被放大、噪点也被放大，微小波动看起来像大地震Too steep: trends and noise are both amplified; tiny fluctuations look like major shocks
  • 过平：趋势被抹平、变化不可见，重要差异被压成一条线Too flat: trends are smoothed out, changes become invisible, and important differences collapse into a single line
  • 45° 黄金区：视觉权重分配合理，人眼判别斜率最准45° sweet spot: visual weight is well balanced, and the human eye judges slope most accurately

实践中，我们通过调整 Y 轴范围来把折线的平均斜率压到 45° 附近 —— 这比盲目扩大/缩小画布尺寸更科学。In practice, we adjust the Y-axis range to push the average slope of the lines toward 45° — this is more scientific than blindly enlarging or shrinking the canvas.

切换到演示 Tab：拖动「斜率调节」滑块，观察 Y 轴范围变化如何把一组折线从过陡调到 45° 黄金区再调到过平。Switch to the Demo tab: drag the "slope" slider and watch how changing the Y-axis range moves a set of lines from too steep, through the 45° sweet spot, to too flat. 
// 核心思想：让 Y 轴的像素跨度和 X 轴差不多
// 这样数据变化 1 单位，视觉上也变化差不多 1 单位 → 45°

var xDomain = [0, 100];   // 时间轴：0~100 月
var yRange  = [0, 500];   // 初始 Y 轴范围（可能过陡或过平）

// 根据用户调整，动态重算 y 轴
function adjustYAxis(targetAngle) {
  // targetAngle 接近 45° → dy/dx ≈ 1
  // y 的像素跨度 / x 的像素跨度 = tan(angle)
  var xPixel = W - M.l - M.r;
  var yPixel = xPixel * Math.tan(targetAngle * Math.PI / 180);

  var yMax = d3.max(data, function (d) { return d.value; });
  var yMin = d3.min(data, function (d) { return d.value; });
  var yDataSpan = yMax - yMin;

  // 在给定像素跨度下，Y 轴应该覆盖的数据范围
  var yDomainSpan = yDataSpan * (yPixel / (H - M.t - M.b));

  y.domain([yMin - yDomainSpan / 2 + yDataSpan / 2,
            yMax + yDomainSpan / 2 - yDataSpan / 2]);
  render();
}

4.5 Marching Squares 等值线

从规则网格标量场提取等值线的经典算法
A classic algorithm for extracting contour lines from a regular-grid scalar field

Marching Squares（行军方格）是 Lorensen & Cline 在 1987 年提出的算法，最初用于医学影像的三维重建（Marching Cubes），二维版本就是 Marching Squares。Marching Squares is an algorithm proposed by Lorensen & Cline in 1987, originally used for 3D reconstruction in medical imaging (Marching Cubes). The 2D version is Marching Squares.

核心思想：对一个 2×2 的方格单元，根据四个角点的值是否大于阈值，得到 2⁴ = 16 种 case，每种 case 预存了连线段的方式。遍历整个网格、拼接线段，就得到一条完整的等值线。Core idea: for a 2×2 grid cell, based on whether each of the four corner values exceeds the threshold, there are 2⁴ = 16 cases, each with a pre-stored line-segment connection pattern. Traverse the whole grid and stitch the segments together to get a complete contour line.

  • 输入：二维标量场（如高斯函数 z = e^(-x²-y²)）Input: 2D scalar field (e.g. Gaussian z = e^(-x²-y²))
  • 处理：d3.contours().size([w, h]).thresholds(n)Process: d3.contours().size([w, h]).thresholds(n)
  • 输出：GeoJSON MultiLineString，用 d3.geoPath 直接渲染Output: GeoJSON MultiLineString, rendered directly with d3.geoPath
D3 实现：d3.contours 已经封装了 Marching Squares 算法，阈值数组决定了等值线的数量和位置。配合 d3.interpolateViridis 可画出漂亮的彩色等值线图。D3 Implementation: d3.contours already wraps the Marching Squares algorithm; the threshold array determines the number and position of contour lines. Combined with d3.interpolateViridis, you can draw beautiful colored contour plots. 
// 1) 生成二维标量场（以高斯函数为例）
var n = 80, m = 40;
var values = new Array(n * m);
var cx = n / 2, cy = m / 2, sigma = 12;

for (var j = 0; j < m; j++) {
  for (var i = 0; i < n; i++) {
    var dx = i - cx, dy = j - cy;
    values[j * n + i] = Math.exp(-(dx * dx + dy * dy) / (2 * sigma * sigma));
  }
}

// 2) d3.contours —— Marching Squares 实现
var contours = d3.contours()
  .size([n, m])
  .thresholds(d3.range(0.05, 0.95, 0.05))(values);

// 3) d3.geoPath 渲染 GeoJSON MultiLineString
var pathGen = d3.geoPath();
var colorScale = d3.scaleSequential(d3.interpolateViridis)
  .domain([0, 1]);

svg.append('g').selectAll('path')
  .data(contours).enter().append('path')
  .attr('d', pathGen)
  .attr('fill', 'none')
  .attr('stroke', function (d) { return colorScale(d.value); })
  .attr('stroke-width', 1.2);
16 种 Case：每个 2×2 方格根据四角二进制值（0/1）决定连哪条对角线。d3.contours 内部已经处理了这些边界情况和 saddle point 歧义。16 Cases: Each 2×2 cell decides which diagonal to connect based on the four corner binary values (0/1). d3.contours already handles these edge cases and saddle-point ambiguities internally.
