6.1 网页基础概念

HTML / CSS / JS 三层分离，是现代网页的骨架
HTML / CSS / JS three-layer separation — the skeleton of modern web pages

一个标准网页由三层组成，各司其职：

  • HTML（结构层）：语义化标签，定义页面内容骨架
  • CSS（表现层）：控制布局、颜色、字体、响应式适配
  • JavaScript（行为层）：交互逻辑、数据绑定、D3 可视化渲染
隔离原则：结构、样式、行为必须分离到独立文件（.html / .css / .js），避免内联样式和脚本。

DOM 树

浏览器解析 HTML 后构建 DOM（Document Object Model）树。CSS 选择器、D3 的 select/selectAll 都是在这棵树上操作节点。

CSS 盒模型

每个元素 = margin + border + padding + content。box-sizing: border-box 让 width 包含 padding 和 border，计算更直观。

📐 布局设计五原则（Design Principles）

语法只是手段，设计原则才是决定页面"好不好看、好不好用"的根本。以下五条原则适用于所有 UI 布局：

  • ① 对比（Contrast）：通过字号、颜色、粗细制造视觉焦点。标题必须比正文大且粗，主按钮用实色填充、次按钮用描边。没有对比 = 没有层次。
  • ② 重复（Repetition）：统一的圆角（如全用 12px）、统一的间距系统（如 4/8/16/24px）、统一的色彩调色板。重复带来专业感和一致性。
  • ③ 对齐（Alignment）：所有元素沿隐形的网格线对齐，不要让元素随意摆放。左对齐是正文最安全的选择，居中对齐用于标题和短文本。
  • ④ 亲密性（Proximity）：相关元素靠近，无关元素拉开距离。标题和它的段落间距小，不同段落组间距大——用间距代替分割线。
  • ⑤ 留白（Whitespace）：不要怕空。充足的留白让内容呼吸，提升可读性和高级感。内容拥挤 = 信息过载。
口诀：对比造焦点，重复造统一，对齐造秩序，亲密造分组，留白造呼吸。五条原则同时满足，页面自然专业。

🗂️ 视觉层次与信息架构

布局的本质是信息架构——决定"什么最重要、什么次要、什么可以折叠"。视觉层次通过三层实现：

  • 一级（主信息）：页面标题、核心数据、主操作按钮 —— 用最大字号 + 品牌色
  • 二级（辅助信息）：副标题、图表标签、导航项 —— 中等字号 + 中性色
  • 三级（元信息）：时间戳、脚注、辅助说明 —— 小字号 + 弱化色

6.2 Flex 布局原理

一维弹性布局，主轴 + 交叉轴
One-dimensional flexible layout with main axis and cross axis

Flexbox 是 CSS 布局的革命性模块，专为一维排列设计：

  • 容器属性：display: flex 开启；flex-direction 控制主轴方向；justify-content 主轴对齐；align-items 交叉轴对齐
  • 子项属性：flex-grow 伸展比例；flex-shrink 收缩比例；flex-basis 初始尺寸；order 视觉排序
  • 换行：flex-wrap: wrap 允许子项溢出时换行
口诀：父元素 display:flex + flex-direction 定方向 + justify-content / align-items 定对齐；子元素用 flex: 1 等分剩余空间。

常见场景

导航栏横向排列、表单字段对齐、卡片列表、垂直居中（justify-content: center; align-items: center）。

🎯 案例应用：仪表盘顶部导航栏

用 Flex 实现仪表盘的顶部导航栏，包含 Logo、导航菜单、用户头像三部分：

  • Logo 区：左对齐，用 align-items: center 让图标和文字垂直居中
  • 导航菜单：中间区域，用 flex: 1 占据剩余空间，内部再用 Flex 横向排列菜单项
  • 用户区：右对齐，头像和用户名用 Flex 横向排列
设计原则体现：对齐（所有元素垂直居中）、亲密性（菜单项间距小、与 Logo 间距大）、留白（导航栏高度 60px，内边距充足）。

关键代码 ① 导航栏 FlexKey Code ① Navbar with Flex

.site-nav .nav-inner {
  max-width: 1280px;
  margin: 0 auto;
  height: 60px;
  display: flex;          /* 开启弹性 */
  align-items: center;    /* 交叉轴居中（垂直居中） */
  gap: 8px;               /* 子项间距 */
}
.site-nav .spacer {
  flex: 1;                /* 占据剩余空间 */
}

关键点解释：flex: 1 1 320px 表示 grow=1（等分剩余）、shrink=1（可收缩）、basis=320px（初始宽度）。这是响应式卡片列表的经典写法。

6.3 Grid 网格布局

二维网格系统，网页布局的终极武器
Two-dimensional grid system — the ultimate weapon for web layout

CSS Grid 是真正的二维布局引擎，比 Flex 更强大：

  • 容器定义网格：display: grid + grid-template-columns / rows
  • 轨道尺寸：固定像素、百分比、fr 剩余空间单位、auto 自适应、minmax() 范围函数
  • 子项放置：grid-column / row: span N 跨单元格；grid-area 命名区域
  • 自动布局：grid-auto-flow 控制填充方向
最佳实践：页面整体骨架（头部 / 侧栏 / 主区 / 底部）用 Grid；内部组件内的一维排列用 Flex。组合使用威力最大。

🎯 案例应用：仪表盘图表卡片网格

仪表盘主体是多个图表卡片的网格布局。用 Grid 实现 12 列响应式网格：

  • 大屏（≥1200px）：grid-template-columns: repeat(12, 1fr)，大图表跨 6 列、小图表跨 4 列
  • 中屏（768-1199px）：repeat(6, 1fr)，大图表跨 6 列、小图表跨 3 列
  • 小屏（<768px）：1fr，所有卡片单列堆叠
设计原则体现：重复（卡片统一圆角、统一内边距）、对齐（网格线严格对齐）、对比（主图表占更大面积吸引注意力）。

关键代码 ① 首页卡片网格Key Code ① Homepage Card Grid

/* 首页：3 列响应式卡片网格 */
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 22px;
}
@media (max-width: 1024px) {
  grid-template-columns: repeat(2, 1fr);
}
@media (max-width: 640px) {
  grid-template-columns: 1fr;
}

关键代码 ② 章节页双栏Key Code ② Chapter Page Two-Column

/* 章节页：2 列骨架（侧栏 260px + 主区自适应） */
.lesson-layout {
  display: grid;
  grid-template-columns: 260px minmax(0, 1fr);
  gap: 28px;
  align-items: start;
}
@media (max-width: 900px) {
  grid-template-columns: 1fr;
}
关键点解释：minmax(0, 1fr) 是关键——它允许网格轨道收缩到 0，防止内部长文本把列撑破。直接写 1fr 在某些浏览器会溢出。

6.4 双栏页面布局实现

侧边导航 + 主内容区，本课程所有章节页的骨架
Sidebar navigation + main content — the skeleton of every chapter page

双栏（或多栏）布局是文档类网站、后台管理系统的标配：

Grid 实现方案（推荐）

父容器 display: grid; grid-template-columns: 260px minmax(0, 1fr); gap: 28px; —— 侧栏固定 260px，主区自适应剩余空间。

侧边栏固定

侧栏设 position: sticky; top: 80px，滚动时固定在视口顶部，长目录可独立滚动。

响应式适配

@media (max-width: 900px) { grid-template-columns: 1fr; } —— 小屏幕自动折叠为单栏，侧栏移到主区上方。

minmax(0, 1fr) 的意义：防止主内容区被内部长文本撑破网格轨道。直接写 1fr 在某些浏览器会溢出。

🎯 案例应用：仪表盘筛选区 + 图表区

仪表盘采用左侧筛选 + 右侧图表的主从布局：

  • 左侧筛选栏（240px）：专业、性别、学位等级筛选器，sticky 固定，滚动时始终可见
  • 右侧图表区（自适应）：主图表 + 数据卡片，占满剩余空间
  • 交互联动：点击筛选器 → 右侧图表实时更新

🧠 信息架构理论：F 型与 Z 型阅读模式

用户浏览页面有两种典型模式，布局应顺应而非对抗：

  • F 型（内容密集页）：用户先横向扫顶部，再向下扫左侧，重要内容放左上角和左边缘
  • Z 型（营销/着陆页）：用户按 Z 字形浏览，重要 CTA 放右下角
设计原则体现：亲密性（筛选器和图表功能相关但分栏放置，用距离区分主次）、视觉层次（主图表面积最大）。

6.5 Tab 切换组件实现

本课程每个章节页都有讲解 / 关键代码 / 演示三 Tab
Every chapter page uses Read / Code / Demo tabs

Tab 是最常用的信息分段组件：

HTML 结构

一个 .tab-bar 容器含多个 button.tab-btn[data-tab]，与下方多个 .tab-panel#panel-{tab} 通过 data 属性配对。

CSS 核心

.tab-panel { display: none; }，激活态加 .active { display: block; }。按钮激活态高亮底 + 下划线。

JS 逻辑

点击按钮 → 清除所有 active → 当前按钮和对应 panel 加 active。可加过渡动画（opacity + translateY）。

可访问性：生产环境应加 role="tablist" / role="tab" / role="tabpanel" 和 aria-selected、键盘方向键支持。

🎯 案例应用：仪表盘图表类型切换

仪表盘用 Tab 切换同一数据的不同视图：

  • 📊 柱状图 Tab：各专业人数对比
  • 🥧 饼图 Tab：性别比例分布
  • 📈 折线图 Tab：入学年份趋势

切换 Tab 时，SVG 容器不变，只重新渲染内部图形，避免页面跳转。

♿ 可访问性（A11y）理论

好的布局不仅要好看，还要让所有人（包括使用屏幕阅读器的用户）都能使用：

  • 语义化标签：用 nav / main / section 而非全是 div
  • ARIA 属性：aria-selected="true" 标记当前 Tab，aria-controls 关联 panel
  • 键盘导航：左右方向键切换 Tab，Enter/Space 激活
  • 焦点管理：激活的 Tab 应有可见的 :focus 样式

6.6 D3 布局函数使用

布局函数 = 数据 → 坐标 / 尺寸的映射器
Layout functions map data to coordinates and sizes

D3 的 "layout" 模块把层级数据转换成可视化所需的几何信息：

  • 层级布局：d3.hierarchy 包装树形数据 → treemap / pack / partition / cluster / tree 产出坐标
  • 分区布局：d3.pie 生成圆弧数据 → 配合 arc 生成路径
  • 力导向：d3.forceSimulation 模拟物理力，适合网络图

三层 API 模式

hierarchy → layout(d) → 节点/链接数组。以 treemap 为例：d3.treemap().size([W, H]).padding(2)(root)，每个 node 自动带上 x0/y0/x1/y1。

布局对比：演示 Tab 里同一棵树数据会同时渲染 treemap、pack、partition 三种视图，直观感受各自特点。

🎯 案例应用：仪表盘图表选择

仪表盘需要根据数据类型和分析目标选择合适的图表：

  • 比较大小：用柱状图（bar）—— 各专业人数对比
  • 展示占比：用饼图/环形图（pie）—— 性别比例
  • 层级关系：用 treemap —— 学院→专业→班级嵌套
  • 趋势变化：用折线图（line）—— 历年招生人数
  • 分布关联：用散点图（scatter）—— 年龄 vs 成绩

📊 图表选型决策理论

图表不是越花哨越好，选型应遵循"数据→任务→编码"三步骤：

  • 数据类型：分类（专业）、有序（年级）、定量（人数）、时间（入学年份）
  • 分析任务：比较、占比、趋势、分布、关联、层级
  • 视觉编码：位置（最精确）> 长度 > 角度 > 面积 > 体积（最不精确）
核心原则：能用位置编码就不用面积，能用柱状图就不用饼图。人眼对位置和长度的感知最准确，对面积和角度的感知误差大。

关键代码 ① treemap 矩形嵌套Key Code ① Treemap Rectangular Nesting

// 统一层级数据
var root = d3.hierarchy(data).sum(function (d) { return d.value; });

// treemap：矩形嵌套
d3.treemap().size([W, H]).padding(2)(root);
root.leaves().forEach(function (node) {
  // node 上有 x0, y0, x1, y1
  g.append('rect')
    .attr('x', node.x0).attr('y', node.y0)
    .attr('width', node.x1 - node.x0)
    .attr('height', node.y1 - node.y0);
});

关键代码 ② pack 与 partitionKey Code ② Pack and Partition

// pack：圆形嵌套
d3.pack().size([W, H]).padding(3)(root);
root.descendants().forEach(function (node) {
  g.append('circle').attr('cx', node.x).attr('cy', node.y).attr('r', node.r);
});

// partition：旭日图 / 矩形分区
d3.partition().size([H, W])(root);
root.descendants().forEach(function (node) {
  // partition 旭日图用角度 + 半径
});
关键点解释：.sum(d => d.value) 让每个叶子节点携带权重，布局函数据此计算面积/半径。层级数据必须先 d3.hierarchy 包装，不能直接传给布局函数。

Zero-cost hosting — go live in 4 steps

GitHub Pages 是静态课程网站的理想宿主：

部署流程

  • 1. 在 GitHub 新建仓库（如 username/username.github.io 或普通仓库）
  • 2. 把本地项目 push 到仓库 main 分支
  • 3. 仓库 Settings → Pages → Source 选择 main 分支 + /(root)
  • 4. 等待一两分钟，访问 https://username.github.io/repo/
注意事项：仓库名若不是 .github.io 结尾，访问 URL 会带 /repo 子路径。所有相对路径从 HTML 文件位置出发，无需额外配置。不支持后端和 PHP，但对纯静态课程站点完全够用。

本地调试

🏗️ 整体布局架构

仪表盘分三层，自上而下：

  • ① 顶部导航栏（Flex）：Logo + 页面标题 + 全局筛选器（6.2 Flex 知识点）
  • ② 数据概览卡片行（Grid）：4 个 KPI 卡片并排，展示总人数、男女人数、专业数、平均年龄（6.3 Grid 知识点）
  • ③ 主内容区（双栏 Grid）：左侧筛选面板 + 右侧图表网格（6.4 双栏知识点）

📊 图表区布局

主内容区右侧用 12 列 Grid 排布 3 个图表：

  • 柱状图（跨 6 列）：各专业人数对比 — 主图表，面积最大
  • 饼图（跨 4 列）：性别比例 — 辅助图表
  • 折线图（跨 6 列）：历年招生趋势 — 跨满底部
设计原则落地：对比（主图表跨 6 列，辅图表跨 4 列，用面积区分主次）、重复（所有卡片统一圆角 12px、统一内边距 20px）、对齐（网格线严格对齐）、亲密性（同组图表间距小，不同组间距大）、留白（卡片间 gap: 20px，内容不拥挤）。

🔄 交互设计

  • Tab 切换图表类型（6.5）：同一区域用 Tab 在柱状图/饼图/折线图间切换
  • 筛选联动（6.4）：左侧勾选专业 → 右侧图表过滤数据并重绘
  • D3 渲染（6.6）：每个图表用对应 D3 布局函数生成

// 筛选器点击 → 过滤数据 → 重绘图表
d3.selectAll('.filter-item').on('click', function () {
  var selected = d3.select(this).attr('data-major');
  var filtered = students.filter(function (d) {
    return d.major === selected;
  });
  renderBarChart(filtered);   // 重绘柱状图
  renderPieChart(filtered);   // 重绘饼图
});

// D3 柱状图渲染
function renderBarChart(data) {
  var svg = d3.select('#bar-chart');
  svg.selectAll('rect').data(data).join('rect')
    .attr('x', (d, i) => i * 40)
    .attr('y', d => height - d.count * 5)
    .attr('width', 32)
    .attr('height', d => d.count * 5)
    .attr('fill', '#3b82f6');
}
